P0（必须优先处理）

P0-1 仓库包含大量不应提交的产物/依赖
- 现象（目录/文件类型）：
  - robot/*/install、robot/*/build、robot/ros2ws/ros2ws/log：典型 colcon/ROS2 产物
  - mobile/node_modules：前端依赖产物
  - robot/audio_ros2/audio_ros2/voice/*/*.so、assets/log/*.log：发布制品/运行日志
- 风险：
  - 仓库体积膨胀、review 噪音极大、可复现性差（产物与源码不一致）
  - 日志/制品可能包含内部地址与运行信息
- 建议：
  - 产物与依赖从源码仓库移除；改为 release artifact / 制品库管理
  - 若使用 git：配置 .gitignore 忽略 build/install/log/node_modules 等

P0-2 硬编码服务地址/端口/绑定地址（不可移植 + 内部拓扑泄漏）
- 位置：
  - robot/audio_ros2/audio_ros2/voice/robot_voice/configs/server_cfg.py
- 例子：
  - ChatTTS URL 写死：http://10.10.100.100:9966/tts
  - CosyVoice 写死：cosyvoice.x-humanoid-cloud.com:9966
  - VoiceSocketServer 写死 host="localhost", port=8765
- 风险：
  - 切环境（赛场/真机/仿真/不同网络）即不可用
  - 对外发布时暴露内网 IP/域名
- 建议：
  - 改为配置驱动（环境变量/配置文件），提供 sample 配置与默认值

P0-3 语音服务端退出/清理不可靠（已知 Ctrl-C 问题）
- 位置：
  - robot/audio_ros2/audio_ros2/voice/robot_voice/server_ros2.py
- 现象：
  - CheckXFNetwork 有 TODO：可能导致程序无法 Ctrl-C 退出
  - voice_server.start() 很可能阻塞，清理逻辑未用 try/finally 保证可达
- 风险：
  - 服务无法优雅停机、资源泄漏、重启/守护进程行为异常
- 建议：
  - 用 try/except KeyboardInterrupt/finally 包裹启动流程，确保 stop 顺序
  - 线程/定时器统一基于 threading.Event 可中断循环
  - 明确主线程/子线程职责（建议 rclpy.spin 在主线程或统一管理）

P1（应尽快修）

P1-1 明显逻辑 bug：无音频判断写错
- 位置：
  - robot/audio_ros2/audio_ros2/voice/robot_voice/configs/server_cfg.py
- 问题：
  - 用 len(DEFAULT_VOICE_DIR) 判断“是否有音频”，但 DEFAULT_VOICE_DIR 是常量字符串，不会为 0
- 影响：
  - music_dir 为空时仍继续执行，后续可能异常或逻辑不符合预期
- 建议：
  - 改为 if len(file_list) == 0: ...（或直接 if not file_list）

P1-2 setup.sh 含明文 Wi-Fi 密码 + 大量系统级危险操作
- 位置：
  - robot/audio_ros2/audio_ros2/setup.sh
- 典型问题：
  - 明文 SSID/密码：nmcli ... "人形机器人" password "88888888"
  - 修改 /etc/sysctl.conf、写 iptables、安装系统包、adb reboot
  - 删除匹配安装包：find ... -name "audio_ros2-*.tar.gz" -exec rm -f {} \;
- 风险：
  - 误运行导致系统状态被不可逆改变；密码泄漏；不同平台/现场环境不可用
- 建议：
  - 拆分为“检查脚本”和“执行脚本”，高危步骤要求显式确认
  - 敏感信息走 env/交互输入，不写死在仓库
  - 增加 set -euo pipefail、dry-run 模式、日志输出与回滚说明

P1-3 前端控制接口缺少超时与错误处理
- 位置：
  - mobile/app/services/controlApi.ts
- 问题：
  - fetch 无超时；res.ok 为 false 也直接尝试 res.json；错误信息被吞
- 建议：
  - AbortController + 超时；对非 2xx 返回携带 status/statusText/message

P1-4 摇杆重复发送存在洪泛与“多 interval”风险
- 位置：
  - mobile/app/components/ControlJoystick.tsx
- 问题：
  - pointerdown 会开启 setInterval，若异常路径/重复触发，可能叠加多个 interval
  - 松手仅停止发送，没有显式“停止/idle”命令（看后端协议是否需要）
- 建议：
  - handleStart 先清理旧 interval 再启动
  - 统一节流/去抖策略；必要时在 handleEnd 发送 stop/idle

P1-5 kaiwu_agent 依赖私有 git 源与潜在凭证泄漏风险
- 位置：
  - robot/audio_ros2/audio_ros2/voice/kaiwu_agent/requirements.txt
- 现象：
  - git+http://kevin:...@10.0.3.101/...（包含用户名/疑似 token/密码片段）
- 风险：
  - 凭证泄漏（严重）；外部环境无法安装依赖
- 建议：
  - 立即移除明文凭证；改为无凭证 URL + 文档说明如何注入凭证
  - 发布版依赖建议用可公开拉取的方式或离线包制品
